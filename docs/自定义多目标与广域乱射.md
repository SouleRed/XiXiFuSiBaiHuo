# 自定义多目标与广域乱射（CustomCombat）

给卡牌加「攻击容量 > 1」的多目标能力，以及边狱巴士式的**广域乱射**（每枚硬币随机挑一个目标打）。
实现由协助者提供，位于 `Source\Shared\CustomCombat\`。

## 涉及文件

| 文件 | 职责 |
|---|---|
| `CustomCombatTargeting.cs` | 目标模型、敌人自动分配、玩家多目标选择 UI、容量接口 |
| `CustomCombatResolution.cs` | 每个攻击骰的伤害分派（主目标 / 副目标 / 随机乱射） |
| `CustomCombatPlayback.cs` | 演出：镜头与命中特效跟随实际被打的目标 |
| `CustomCombatOneSideManager.cs` | 一边攻击流程，调用 `ResolveDie` |
| `CustomCombatParryingManager.cs` | 拼点流程，同样调用 `ResolveDie` |
| `Source\Shared\Patches\ModPatches.cs` | 接管 `AddCard` / `ApplySelectedCard` / 卡 UI 交互 |

## 1. 目标模型

原版一页只有 `target` 与 `targetSlotOrder`，这里额外用 `subTargets` 存副目标：

```csharp
page.subTargets = new List<BattlePlayingCardDataInUnitModel.SubTarget>();
```

容量由接口提供，**不改 `CardInfo` 的骰子结构**：

```csharp
internal interface ICustomAttackCapacity { int AttackCapacity { get; } }
internal interface ICustomRandomBarrage : ICustomAttackCapacity { }   // 空接口，纯标记
```

- `ICustomAttackCapacity`：多目标，每个副目标各挨一次
- `ICustomRandomBarrage`：再实现这个，变成广域乱射

## 2. 目标怎么来

| 使用方 | 入口 | 行为 |
|---|---|---|
| 敌人 | `BattlePlayingCardSlotDetail.AddCard` 后缀 → `FillAutomatic` | 自动随机补满副目标（随机速度骰） |
| 玩家 | `BattleUnitCardsInHandUI.ApplySelectedCard` 前缀 → `Apply` | 第一次点击走原版 `AddCard`，之后每点一个敌人加一个副目标 |
| 玩家结束 | `BattleUnitCardsInHandUI.Update` 前缀 + 右键 | 右键确认（拦截右键，避免穿透成卸牌） |
| 玩家编辑中 | 卡 UI 的 `Blocks` | 除正在编辑的卡外，其他卡 UI 失效，防误触 |

## 3. 伤害结算

`CustomCombatResolution.ResolveDie(dice, target)` 是所有攻击骰的统一入口：

```
非多目标页            → 原生 GiveDamage
ICustomRandomBarrage  → ResolveRandomBarrageDie
                         ├ 从 page.Targets（主目标 + 副目标）随机挑一个
                         ├ 挑中主目标 → 正常打主目标（返回 true）
                         └ 挑中副目标 → ResolveSecondaryHit（返回 false，主目标不计受击）
普通多目标            → 先打主目标，再对每个副目标各算一次
```

- 副目标结算会把自己的受击/破绽/回血等数据**并入本骰的主日志**，避免战报错位
- 主目标被完全格挡（`record.isBlockedDice`）时跳过副目标结算
- 演出层用 `frame.IsRandomBarrage` 与 `frame.ActualTarget` 调整镜头与特效，避免"打 A 演 B"

## 4. 新卡怎么接

**第一步：脚本命名**

```csharp
namespace 裁缝之王
{
    public class DiceCardSelfAbility_CX_MyAoE : DiceCardSelfAbilityBase, ICustomAttackCapacity
    {
        public int AttackCapacity => 5;
    }

    public class DiceCardSelfAbility_CX_MyBarrage : DiceCardSelfAbilityBase, ICustomRandomBarrage
    {
        public int AttackCapacity => 3;
    }
}
```

类名必须是 `DiceCardSelfAbility_<Script>`，`<Script>` 与 `CardInfo.xml` 里的 `Script="..."` 一致。

**第二步：CardInfo 不用改多目标**

`<Behaviour>` 的骰子数、目标类型照旧写，容量完全由接口决定。

**第三步：描述标签**

中文：`[攻击容量3][广域乱射] …`
英文：`[Atk Weight 3][Unfocused Volley] …`
韩文：`[공격 가중치 3][광역 난사] …`

（攻击容量、广域乱射属边狱原生系统，用边狱译名，见 [术语对照表](…) 的模块9）

**第四步：跨程序集要开可见性**

接口是 `internal`，其他工程要用必须在 `AssemblyInfo.cs` 加：

```csharp
[assembly: InternalsVisibleTo("XiXiFuSiBaiHuo.RedDice")]
```

**第五步：脚本所在程序集必须已注册**

- 主工程 `Source\`：随主 dll 注册
- 延迟程序集 `Source.RedDice\`：由 `ModInitializer.LoadDeferredRedDiceAbilities` 在确认 RedDice 存在后反射注册（前缀 `DiceCardSelfAbility_` / `DiceCardAbility_`）

## 5. 约束与坑

| 约束 | 说明 |
|---|---|
| 容量 ≤ 1 | 走原版逻辑，不进这套 |
| 副目标必须可控 | `ValidSecondary` 要求 `speedDiceResult[slot].isControlable` |
| 打友方的前提 | 仅当 `page.owner.TeamKill()` 为真 |
| 随机乱射的日志 | 命中副目标时 `ResolveDie` 返回 `false`，主目标不算受击，避免战报重复 |
| 敌人自动分配 | `FillAutomatic` 只在 `AddCard` 时触发，手动改目标不会自动补 |
| 玩家多目标 | 依赖 `BattleUnitCardsInHandUI` 的补丁；若其他 MOD 重写该 UI 需重新确认兼容 |

## 6. 验证

- 实机：出牌后点多个敌人，右键确认，观察是否每个目标都受击
- 广域乱射：同一页多枚硬币，观察每枚硬币打的目标是否随机变化、镜头是否跟随
- 战报：每枚硬币的伤害只记一次，副目标受击出现在对应骰子下
- 日志：延迟程序集注册成功会打印
  `[裁缝之王][RedDice] 已延迟注册红骰脚本：书页=N, 骰子=M`

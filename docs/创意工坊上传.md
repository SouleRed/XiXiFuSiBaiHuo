# 创意工坊上传（自动化）

## 结论

原来的 `SteamworkUploader` 是 **WinForms 图形工具**（拖文件夹 + 填表 + 两个按钮），
没有命令行参数，无法被脚本调用。

所以我们自己做了一个等价的**命令行上传器**，走同一套 Facepunch.Steamworks 接口：

```
Tools\WorkshopUploader\       构建产物 bin\WorkshopUploader.exe
Upload-Workshop.ps1           一键：构建 + 上传
workshop.config.json          工坊物品 ID、标题、简介、标签、更新说明
```

## 首次准备

1. **Steam 客户端必须运行并已登录**（不需要在脚本里填账号密码）
2. 打开 `workshop.config.json`，填写 `itemId`：
   - 已经发布过 → 填工坊链接里的数字，例如
     `https://steamcommunity.com/sharedfiles/filedetails/?id=3841234567`
     则填 `"itemId": "3841234567"`
   - 还没发布 → 留空，用 `-New` 首次上传，成功后把返回的 ID 填进去

## 日常更新

```powershell
# 构建 + 上传（物品 ID 从 config 读取）
.\Upload-Workshop.ps1 -ChangeNote "修复 BGM 开局爆音"

# 只构建并检查参数，不上传
.\Upload-Workshop.ps1 -Check

# 跳过构建，直接上传现在的 MOD根目录
.\Upload-Workshop.ps1 -SkipBuild -ChangeNote "只更新资源"
```

可选参数：

| 参数 | 作用 |
|---|---|
| `-ChangeNote "..."` | 本次更新说明（工坊的 Change Notes） |
| `-Title` / `-Description` | 临时覆盖 config 里的标题/简介 |
| `-Tags "Reception","Skin"` | 覆盖标签 |
| `-Preview 路径` | 覆盖封面图（默认 `MOD根目录\preview.jpg`） |
| `-New` | 创建新物品（忽略 config 的 itemId） |
| `-Public` / `-Private` | 设置可见性 |
| `-Check` | 只打印参数，不连 Steam |
| `-SkipBuild` | 跳过 BuildAndDeploy.ps1 |

## 上传器直接调用

```powershell
Tools\WorkshopUploader\bin\WorkshopUploader.exe `
  --content "MOD根目录" `
  --preview "MOD根目录\preview.jpg" `
  --id 3841234567 `
  --title "标题" --desc "简介" --tag "Reception" `
  --changenote "更新说明" --public
```

`--id` 省略即新建项目。只更新内容时可以不带 `--title/--desc`，保持原样。

## 原理

- `SteamClient.Init(1256670)` 连上本机 Steam 客户端（Library of Ruina 的 AppID）
- `Editor.NewCommunityFile` / `new Editor(new PublishedFileId{Value=id})` 选择新建或更新
- `WithTitle/WithDescription/WithChangeLog/WithPreviewFile/WithContent/WithTag` 填字段
- `SubmitAsync()` 上传，返回 `PublishResult.Success` 与 `FileId`

Facepunch 的 `Editor` 字段是 `internal`，必须用 `With*` 链式方法，不能直接赋值（踩过）。

## 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| `Steam 客户端未就绪` | Steam 没开或没登录 | 启动 Steam 并登录后重试 |
| `该物品还需要在网页端同意创意工坊协议` | 首次发布 | 打开返回的链接，在网页上同意协议 |
| 上传后封面没变 | 预览图路径不对 / 图片规格不符 | 检查 `preview` 路径；工坊封面建议 16:9 |
| 更新后内容没变 | 上传的是旧目录 | 确认 `--content` 指向 `MOD根目录`，且没有加 `-SkipBuild` 而忘了先构建 |
| PowerShell 报中文乱码/解析错误 | `.ps1` 被当成 ANSI 读取 | 脚本必须存成 **UTF-8 带 BOM** |

## 与旧工具的关系

`SteamworkUploader_cn.exe` 仍可继续用（拖拽 + 填表），命令行上传器与它互不冲突：
两者都通过本机 Steam 客户端发布，只是入口不同。日常批量更新建议用脚本，特殊情况再用 GUI。

## 多语言描述（重要）

**结论：Steam 的 ISteamUGC 接口只能改“物品的基础标题/简介”，改不了各语言的翻译槽位。**

实测：

- 用 `--lang japanese` 提交日文标题/简介后，接口返回的默认标题变成了日文
- 再用 `--lang english` 提交英文，默认标题又变回英文
- 说明 `SetItemUpdateLanguage` 只是标记本次提交的语言，写入的仍是同一份基础文本

所以：

| 要做的事 | 怎么做 |
|---|---|
| 内容、封面、更新说明 | 脚本上传（`.\Upload-Workshop.ps1`） |
| 中文/英文/韩文/日文的独立简介 | **只能在 Steam 网页的物品编辑页逐个语言填** |
| 只想更新内容、不动任何文案 | 默认行为即可（脚本自动 `--preserve-meta`） |

`Upload-Workshop.ps1` 默认就走 `--preserve-meta`：先读取服务器现有的基础标题/简介再原样写回，
只有在 `-New` 或 `-UseConfigMeta` 时才会用 config 里的文案覆盖基础文本。

### 常用命令

```powershell

.\Upload-Workshop.ps1 -ChangeNote "修复 BGM 爆音"

.\Upload-Workshop.ps1 -Info
```
